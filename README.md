# RdpGuard

Служба Windows (.NET 8), которая следит за подбором паролей по сети (RDP, SMB и другие сетевые входы)
и банит IP-адреса в Windows Firewall. Каждое следующее нарушение с того же адреса даёт бан в два раза длиннее.
Данные хранятся в SQLite. Один `RdpGuard.exe` — это и служба, и консольная утилита управления.

## Сборка

Нужен .NET SDK 8 или новее.

```bash
dotnet publish src/RdpGuard -c Release -r win-x64 -o publish
```

В `publish\` будут `RdpGuard.exe` (self-contained single file, ~35 МБ; .NET на сервере не нужен)
и `appsettings.json`. Конфиг лежит рядом с exe специально, чтобы его можно было править.

## Установка

Все команды запускаются из **консоли администратора**.

1. Скопируйте `RdpGuard.exe` и `appsettings.json` в постоянную папку, например `C:\Program Files\RdpGuard\`.
   Служба регистрируется с путём к exe, поэтому ставить её из «Загрузок» не стоит.
2. Установите и запустите службу:

   ```bash
   "C:\Program Files\RdpGuard\RdpGuard.exe" install
   ```

   Команда:
   - регистрирует службу `RdpGuard` под LocalSystem с автозапуском и зависимостями от EventLog и MpsSvc;
   - включает перезапуск при сбое (через 5 с, 15 с, 60 с; счётчик сбоев обнуляется через сутки);
   - создаёт источник `RdpGuard` в журнале Application;
   - создаёт БД в `%ProgramData%\RdpGuard\rdpguard.db` и запускает службу (`--no-start` — не запускать).
3. **Первый запуск идёт в режиме DryRun** (`"DryRun": true` в поставляемом `appsettings.json`): служба читает журналы,
   считает попытки и записывает баны в БД, но брандмауэр **не трогает**. Понаблюдайте день-два:

   ```bash
   RdpGuard status
   RdpGuard top --hours 24
   RdpGuard bans --active
   ```

   Убедитесь, что среди банов нет ваших адресов (если есть — `RdpGuard allow <ip|cidr>`).
4. Включите блокировку: в `appsettings.json` поставьте `"DryRun": false` и перезапустите службу:

   ```bash
   sc.exe stop RdpGuard
   ```

   ```bash
   sc.exe start RdpGuard
   ```

   При старте служба сверит брандмауэр с БД и создаст правила для всех активных банов.

> Включите аудит неудачных входов, если он выключен:
> `auditpol /set /subcategory:"Logon" /failure:enable /success:enable`
> (на большинстве серверов он включён по умолчанию). Без него события 4625 не пишутся.

## Как это работает

### Источники событий

| Журнал | Событие | Что берём (по позиции в EventData) |
|---|---|---|
| Security | 4625 — неудачный вход | `TargetUserName` = [5], `LogonType` = [10], `IpAddress` = [19] |
| Security | 4624 — успешный вход | `TargetUserName` = [5], `LogonType` = [8], `IpAddress` = [18] |
| RemoteDesktopServices-RdpCoreTS/Operational | 140 — не удалось проверить подлинность | `ClientIP` = [0] (если журнал есть и включён) |

- Поля читаются **по позиции** (`EventRecord.Properties`), а не из текста сообщения, поэтому язык Windows не важен.
- Учитываются типы входа **3** (сетевой: SMB и RDP с NLA) и **10** (RDP без NLA); список настраивается.
- Одна RDP-попытка часто даёт и 4625, и 140. События из разных журналов с одного IP с разницей до 5 секунд
  (`RdpCoreTsDedupSeconds`) считаются одной попыткой.
- Успешный вход (4624) с **внешнего** адреса не банится: он записывается в таблицу `successes`, в журнал
  Application уходит предупреждение (событие 1003, не чаще раза в час на пару IP+пользователь), активный бан
  с этого адреса снимается, и следующие `SuccessTrustDays` дней адрес не банится.

### Подписка и догрузка пропущенного

Подписка идёт через `EventLogWatcher`. Для каждого журнала в таблице `state` хранится `RecordId` последнего
обработанного события (`bookmark:Security`, `bookmark:<RdpCoreTS>`). При старте служба подписывается
запросом `EventRecordID > закладка` с чтением существующих событий. Watcher сначала отдаёт всё, что было
пропущено, пока служба не работала, а затем новые события, так что промежутка между догрузкой и подпиской нет.
Если журнал очистили и номера записей начались заново, закладка сбрасывается.
При самом первом запуске читаются события за последние `InitialLookbackMinutes` минут.

### Обработка

```
EventLogWatcher (Security) ─┐
EventLogWatcher (RdpCoreTS) ┼─> Channel<WorkItem> ──> GuardEngine (единственный писатель в SQLite)
Таймер 5 с / 60 с ──────────┘                          │  пачка до 1000 событий = 1 транзакция
                                                        └─> FirewallSync (только при изменениях)
```

- Колбэки журналов только кладут событие в очередь и никогда не ждут БД.
- Ошибка в одном событии логируется и не останавливает обработку пачки. Ошибка синхронизации брандмауэра
  повторяется на следующем тике.
- Раз в минуту: снятие истёкших банов, сверка правил брандмауэра с БД, раз в час — удаление попыток старше
  `AttemptRetentionDays`.
- Каждые 5 секунд служба проверяет, не изменил ли CLI данные (`ban`, `unban`, `allow`, `disallow`), и сразу применяет изменения.

### Политика

Бан выдаётся, если с IP было не меньше `MaxFailures` неудачных входов за последние `FailureWindow`
(по времени событий), и при этом:

- адрес не в белом списке;
- с него не было успешного входа за последние `SuccessTrustDays` дней;
- у него сейчас нет активного бана.

Окно не начинается раньше окончания предыдущего бана этого адреса. Поэтому после ручного `unban`
старые попытки не вызывают мгновенный повторный бан.

Белый список состоит из трёх частей:

- встроенные частные диапазоны (`TrustPrivateRanges`): 10/8, 172.16/12, 192.168/16, 127/8, 169.254/16, 100.64/10,
  `::1`, IPv6 link-local `fe80::/10` и ULA `fc00::/7`;
- `Whitelist:Cidrs` из конфига;
- записи, добавленные командой `allow`.

Поддерживаются IPv4 и IPv6, адреса вида `::ffff:a.b.c.d` приводятся к IPv4.

### Брандмауэр

- Работа идёт через COM API (`HNetCfg.FwPolicy2` / `INetFwPolicy2`), `netsh` не запускается.
- Правила называются `RdpGuard-Block-01`, `RdpGuard-Block-02`, … (группа `RdpGuard`): входящие, блокировать,
  все профили, до `MaxAddressesPerRule` (≤ 1000) адресов в правиле.
- `Scope`: `AllPorts` блокирует весь входящий трафик с адреса, `RdpPort` блокирует только TCP-порт RDP
  (берётся из реестра, если `RdpPort = 0`).
- Адреса не перетасовываются между правилами. Адрес, уже стоящий в правиле, там и остаётся, новые занимают
  свободные места. Поэтому бан или разбан одного адреса перезаписывает одно правило.
- При старте и раз в минуту служба сверяет брандмауэр с БД. Правила с префиксом **`RdpGuard-`**, которых
  не должно быть, удаляются, а изменённые вручную восстанавливаются. **Правила без этого префикса никогда не трогаются.**
- Правило с пустым списком адресов в Windows означает «любой адрес», поэтому такое правило никогда не создаётся:
  опустевшее правило удаляется.

## Нарастание срока бана

Срок бана за нарушение номер *n*:

```
срок = BaseBanDuration × 2^(n−1), но не больше MaxBanDuration
```

С настройками по умолчанию (1 сутки, потолок 30 суток):

| Нарушение | 1 | 2 | 3 | 4 | 5 | 6 и далее |
|---|---|---|---|---|---|---|
| Срок | 1 сут | 2 сут | 4 сут | 8 сут | 16 сут | 30 сут (потолок) |

- **Навсегда**: при `PermanentAfterOffenses = K` (K > 0) нарушение номер K+1 и все следующие дают бан
  без срока (`expires_at_utc = NULL`). По умолчанию 0, то есть выключено.
- **Сброс счётчика**: если адрес не появлялся `OffenseResetDays` дней (по умолчанию 90), следующее нарушение
  снова считается первым. Отсчёт идёт от более позднего из двух моментов: последней попытки или окончания последнего бана.
  Иначе 30-дневный бан сам по себе «съедал» бы часть этих 90 дней.
- Номер нарушения хранится в `ips.offenses`, у каждого бана — в `bans.offense_no`.
- Срок отсчитывается от момента бана. Если служба догружает старые события после простоя, бан начинается
  в момент обработки.

## Конфигурация

`appsettings.json` рядом с `RdpGuard.exe`, секция `RdpGuard`. Поддерживаются комментарии. После правки
перезапустите службу. Любой параметр можно переопределить переменной окружения с префиксом `RDPGUARD_`,
например `RDPGUARD_RdpGuard__DryRun=false`.

| Параметр | По умолчанию | Описание |
|---|---|---|
| `DryRun` | `true` | Считать и логировать, но не менять брандмауэр |
| `DataDirectory` | `%ProgramData%\RdpGuard` | БД и папка `logs` |
| `Detection:LogonTypes` | `[3, 10]` | Учитываемые типы входа |
| `Detection:EnableRdpCoreTs` | `true` | Читать событие 140 из RdpCoreTS/Operational |
| `Detection:RdpCoreTsDedupSeconds` | `5` | Окно склейки 4625 и 140 |
| `Detection:InitialLookbackMinutes` | `60` | Глубина чтения при первом запуске |
| `Detection:TrackSuccessfulLogons` | `true` | Записывать 4624 с внешних адресов |
| `Policy:MaxFailures` | `10` | Порог N |
| `Policy:FailureWindow` | `00:10:00` | Окно W |
| `Policy:BaseBanDuration` | `1.00:00:00` | Срок первого бана |
| `Policy:MaxBanDuration` | `30.00:00:00` | Потолок срока |
| `Policy:PermanentAfterOffenses` | `0` | K: после K нарушений бан навсегда (0 = выкл.) |
| `Policy:OffenseResetDays` | `90` | Через сколько дней тишины сбрасывать счётчик (0 = никогда) |
| `Policy:SuccessTrustDays` | `30` | Не банить адрес столько дней после успешного входа (0 = выкл.) |
| `Policy:SuccessfulLogonLiftsBan` | `true` | Успешный вход снимает активный бан |
| `Whitelist:TrustPrivateRanges` | `true` | Не банить частные диапазоны |
| `Whitelist:Cidrs` | `[]` | Дополнительные адреса и сети |
| `Firewall:Scope` | `AllPorts` | `AllPorts` или `RdpPort` |
| `Firewall:RdpPort` | `0` | Порт для `RdpPort`; 0 — из реестра (по умолчанию 3389) |
| `Firewall:MaxAddressesPerRule` | `1000` | Адресов в одном правиле (1..1000) |
| `Storage:AttemptRetentionDays` | `30` | Срок хранения `attempts` и `successes` |
| `FileLog:Enabled` / `MaxFileSizeMB` / `RetainedFiles` | `true` / `10` / `10` | Файловый лог с ротацией |

Формат длительностей — `d.hh:mm:ss`: `"00:30:00"` — 30 минут, `"7.00:00:00"` — 7 суток.

## Команды CLI

Все команды требуют консоли администратора. Время в выводе — местное.

| Команда | Что делает |
|---|---|
| `install [--no-start]` | Зарегистрировать службу (или обновить путь у существующей) и запустить |
| `uninstall [--purge]` | Остановить и удалить службу и **все** правила `RdpGuard-*`; `--purge` удаляет ещё БД, логи и источник журнала |
| `run` | Запустить в консоли (для диагностики; служба должна быть остановлена) |
| `status` | Состояние службы, режим, число активных банов, попытки за час и сутки, правила брандмауэра |
| `bans [--active] [--limit N] [--ip IP]` | Таблица банов: номер нарушения, когда выдан, до какого времени, сколько осталось, статус |
| `top [--hours 24] [--limit 20]` | Топ IP по попыткам (с самыми подбираемыми именами) и топ имён пользователей |
| `ban <ip> [--days N \| --hours N \| --permanent] [--reason TEXT] [--force]` | Ручной бан. Без срока — по политике (нарастающий). `--force` — банить, даже если с адреса недавно был успешный вход |
| `unban <ip> [--reset]` | Снять бан; `--reset` обнуляет счётчик нарушений |
| `allow <ip\|cidr> [--note TEXT]` | Добавить в белый список (активные баны из этой сети снимаются) |
| `disallow <ip\|cidr>` | Удалить запись, добавленную `allow` |
| `whitelist` | Показать весь белый список (встроенный, из конфига, из БД) |
| `export --csv [--out DIR]` | Выгрузить `ips.csv` и `bans.csv` (UTF-8, время в UTC) |
| `sync` | Сверить брандмауэр с БД прямо сейчас |

Примеры:

```bash
RdpGuard ban 203.0.113.7 --days 7 --reason "scanner"
```

```bash
RdpGuard allow 198.51.100.0/24 --note "office"
```

```bash
RdpGuard export --csv --out C:\Temp\rdpguard
```

Если служба запущена, она применяет изменения из CLI в течение ~5 секунд. Если не запущена и DryRun выключен,
CLI сам синхронизирует брандмауэр.

## Логи

**Журнал Application, источник `RdpGuard`.** Туда пишутся аудит и всё уровня Warning и выше:

| ID | Событие |
|---|---|
| 1000 | Служба запущена (режим, число банов) |
| 1001 | Бан (адрес, номер нарушения, срок, причина) |
| 1002 | Снятие бана (истёк срок, успешный вход, белый список) |
| 1003 | Успешный вход с внешнего адреса |
| 1004 / 1005 | Ручной бан / разбан из CLI |
| 1006 | Изменение белого списка |
| 1900 / 1901 | Ошибки обработки / брандмауэра |

**Файл** `%ProgramData%\RdpGuard\logs\rdpguard.log` с ротацией по размеру: `rdpguard.1.log` … `rdpguard.N.log`.
Уровни задаются стандартной секцией `Logging` (провайдер `File`).

## Откат и удаление

```bash
RdpGuard uninstall
```

Команда останавливает и удаляет службу и удаляет **все** правила брандмауэра, имя которых начинается с `RdpGuard-`.
Другие правила не затрагиваются. БД и логи остаются, `uninstall --purge` удаляет и их.

Быстро отключить блокировку, не удаляя службу: поставьте `"DryRun": true` и выполните `RdpGuard uninstall`
или удалите правила вручную. Служба в DryRun не создаёт правила заново.

Удалить правила вручную (PowerShell), если exe уже нет:

```powershell
Get-NetFirewallRule -DisplayName 'RdpGuard-*' | Remove-NetFirewallRule
```

## Схема БД

SQLite в режиме WAL, файл `rdpguard.db`. Версия схемы хранится в `state.schema_version`, миграции применяются
при открытии БД.

| Таблица | Назначение |
|---|---|
| `attempts(id, ts_utc, ip, user_name, logon_type, event_id, record_id)` | Неудачные попытки; индекс `(ip, ts_utc)`; хранятся `AttemptRetentionDays` |
| `bans(id, ip, banned_at_utc, expires_at_utc, offense_no, reason, failures_in_window, unbanned_at_utc, unban_reason)` | История банов; `expires_at_utc = NULL` — навсегда |
| `ips(ip, first_seen_utc, last_seen_utc, total_failures, offenses, last_offense_utc, last_success_utc, note, whitelisted)` | Сводка по адресам |
| `successes(id, ts_utc, ip, user_name, logon_type, record_id)` | Успешные входы с внешних адресов |
| `whitelist(cidr, added_utc, note)` | Записи `allow` |
| `state(key, value)` | Закладки журналов, версия схемы, ревизия изменений из CLI |

Время хранится в UTC в формате `yyyy-MM-dd HH:mm:ss.fff`.

```bash
dotnet test
```

Структура:

```
src/RdpGuard/
  Cli/            install/uninstall/status/bans/top/ban/unban/allow/disallow/export
  Configuration/  GuardOptions (appsettings.json)
  Data/           GuardDb (SQLite, миграции), Repository
  Engine/         GuardEngine (очередь -> БД -> брандмауэр), AdminOperations
  Events/         EventParser, EventLogAuthSource (EventLogWatcher), дедупликация 4625/140
  Firewall/       IFirewall, ComFirewall (INetFwPolicy2), FirewallSync (разбиение и сверка)
  Hosting/        Windows Service host
  Logging/        файловый лог с ротацией
  Net/            IP, CIDR, белый список
  Policy/         BanPolicy (чистая логика без ввода-вывода)
tests/RdpGuard.Tests/
  BanPolicyTests             окно, порог, нарастание, потолок, навсегда, сброс счётчика, белый список, успешный вход
  WhitelistAndParsingTests   диапазоны, CIDR, нормализация IP, разбор событий по позициям, XPath, дедупликация
  FirewallSyncTests          пачки по 1000, стабильность правил, сверка, чужие правила не трогаются
  GuardEngineTests           поток 4625 с нескольких IP -> баны в SQLite и в фейковом брандмауэре
```

Брандмауэр в тестах — `FakeFirewall` (за интерфейсом `IFirewall`), источник событий — `FakeEventSource`,
время — подменяемый `TimeProvider`.
